# Interactive Sales Training deck (LMS-K12, G2G, Enterprise Brain)

`G2G-Sales-Training-Interactive.pptx` is a native, editable PowerPoint with branching scenarios. Run it in **Slide Show mode (F5)**: links only work there.
`NAVIGATION-MAP.md` lists every slide and where each button leads.

## Regenerate / test
```
cd generator
npm install
node build.js      # writes the .pptx, NAVIGATION-MAP.md, graph.json
node validate.js   # reads the saved .pptx XML and checks links and branching
```
Content lives in `generator/content/*.js` (one file per product). Edit the text there and rebuild. The deck can also be edited by hand in PowerPoint; a rebuild overwrites hand edits.

## Structure (per product, about 93 slides)
Home -> Product hub -> overview, modules (with detail slides), problems, customers, benefits/USPs, proof, readiness, "what we cannot claim" -> persona -> 8 decisions covering the 11 sales stages -> outcomes (Won / Won with concessions / Stalled / Lost).
Each decision has 3 options; each option has its own feedback slide (reaction, consequence, coaching) with Continue and Return to decision. Poor decisions lead to a recovery slide or a lost deal.
Customer confidence is stored by *which slide you are on*: a Strong lane and a Wavering lane (the first decision has only the Strong lane).

## Known gaps and limits
- **Not documented anywhere:** pricing, ROI, USPs, testimonials, case studies, an approved client count. The deck says so and teaches "confirm and come back" instead.
- **No screenshots exist** in the repos; slides carry dashed placeholders to replace by hand. The live study-deck, H5P-style reference and portfolio pages needed a login and could not be inspected.
- **Enterprise Brain** has only five offer one-liners; its repo is not on this machine. **G2G** docs cover HRIT and reports but have no pages for Talent, Capability, G2G LMS, Task or Organization modules, and describe CCB for educational organisations.
- Naming: the portfolio calls the K-12 product ScholarClone ("Scholar K-12"); owner confirmed LMS-K12 = ScholarClone. The expansion of "G2G" is undocumented.
- Without macros PowerPoint cannot keep a score or log decisions. The outcome slide is the performance evaluation; nothing is recorded in the LMS.
- The deck is a file. It is **not yet attached to My Learning**: it can be added as a `pptx` lesson (the lesson viewer renders pptx through Office Online, which needs the file at a public URL, and Office Online may not run slide-jump links as PowerPoint does).

## G2G Sales Presentation (the deck to use with customers)
`G2G-Sales-Presentation.pptx` is a G2G-only sales deck (91 slides, native PowerPoint links, no macros). Run it in Slide Show mode (F5).
- Title, then "What matters most to you?" (five need-based entry points plus all modules).
- Eight modules, each with a "typical situation / what G2G does / what it means for you" slide and a "who gets what" slide by role.
- "Where G2G is today": what is built and what is still being completed.
- Ten customer questions and objections with honest answers and the documented facts behind each.
- A six-decision conversation simulator with a fictional customer: every choice has its own result, poor choices get one recovery chance, and the endings are won, won with concessions, stalled or lost.

Regenerate: `cd generator && node build-sales-ppt.js`. Content: `generator/content/g2g-sales.js` (modules, questions) and `generator/content/g2g.js` (the conversation). Checked by opening the file in PowerPoint (all 431 links resolve) and by built-in graph checks (every slide reachable, each decision's options lead to different slides).
No pricing, ROI, client count or competitor comparison is claimed, because none is documented. "Typical situation" lines describe the customer's world, not a G2G claim.

### Images in the G2G Sales Presentation
All images are listed with source, creator, licence and credit line in `assets/ASSET-REFERENCES.md` (generated by `build-sales-ppt.js` from `assets/manifest-*.json`; the pictures themselves are in the database). Every picture on a slide is tagged "ILLUSTRATION - NOT A G2G SCREEN" or "DIAGRAM DRAWN FOR THIS DECK"; the deck contains no real G2G screenshot because none exists in the repositories.
Photos and illustrations come from Wikimedia Commons (licence read from the Commons API), unDraw and Pexels (their published licences). Diagrams for Attendance, Competency, KASBA, Gap assessment and Reports, and the overview diagram, are drawn natively from documented facts. Dribbble was not used (design reference only).
Rejected after review: fingerprint-scanner photos (would imply biometric attendance, which the docs list only as a possible v2 idea), a calendar printed "MATERNITY LEAVE" (not a documented leave type), a branded robot photo, and a Grafana server dashboard (not HR reporting, carries a product logo).

## G2G Sales Presentation, salesperson-led (40 slides)

Used by a G2G salesperson in a live meeting, not for self-study. The salesperson picks the route; there is no fixed sequence.

This folder lives in the frontend (`g2gv0/scripts/sales-training`). From `generator/`: run `npm ci` once, then

- `npm run build:ppt` builds `G2G-Sales-Branching-Presentation.pptx` (Slide Show mode, F5) from `content/g2g-guide.js`, `g2g-story.js` and `g2g-sales.js`.
- `npm run export:deck` writes the browser version (My Learning) to `public/sales-training/sales/deck.json`, from the same graph.

Link graph: `generator/story-graph.json`. Image and icon credits: `assets/ASSET-REFERENCES-branching.md`.

**Pictures are stored in the database, not in files.** Table `sales_training_images` (hp_erp backend), served by `GET /api/sales-training/images/{slug}` and passed through by the frontend route `app/api/sales-training/images/[slug]/route.ts`.
- The deck names pictures only by that URL. The PowerPoint and export steps first run `fetch-images.js`, which downloads what they need into `generator/.cache` from `SALES_IMAGE_API` (default `http://127.0.0.1:8000/api`, the local backend).
- To add or change a picture: put it in `assets/manifest-*.json`'s source or run `node export-story-deck.js` (module/role diagrams), then `node stage-assets.js` and, in hp_erp, `php artisan sales-training:import-images "<generator>/out/assets"` (or `out/images` for the diagrams). Rows are updated in place.
- Backend files (hp_erp): migration `2026_12_18_100000_create_sales_training_images_table.php`, `SalesTrainingImageController`, command `SalesTrainingImportImages`, and the route in `routes/api.php`.

Every slide has a top navigation bar: Back | Home | Roles | Modules | Business Problems | Solutions | Sales Scenarios.
Roles (6) -> role slide (its modules and what the role needs) -> module talk track (problem solved, why the customer needs it, roles,
what each role needs, how G2G addresses it, value, discovery question, clickable features) -> features slide (three features to demonstrate:
what to show, why it matters). Business Problems -> live conversation or the Solutions matrix. Sales Scenarios: four conversations where
the salesperson asks and clicks what the customer says (each answer opens a different module, feature or solution), customer questions
(cost, other clients, what is ready), and the closing slide with next steps.
Roles are only those in the G2G v1 docs; "Department Head" is not a documented G2G role. Icons: Lucide (ISC).
